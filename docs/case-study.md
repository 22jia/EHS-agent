# EHS Agent · 产品案例

## 问题与目标

法规文字、检查动作与整改记录是不同层次的信息。产品希望把“读过规定”转成“知道查什么、怎样留证、由谁继续处理”，并保留人工审核的位置。

案例依据是本地 EHS Loop README 与当前后端实现；本仓库尚未发布应用源码，不将历史架构草案中的状态当作最新实现。

## 三个产品取舍

| 决策 | 目的 | 仍需验证 |
| --- | --- | --- |
| 使用完整库内法规和企业说明 | 保留上下文，暴露条件缺口 | 长文本覆盖与适用性判断质量 |
| 生成草稿后校验引用 | 降低编造原文、错误拼接 | 引文与检查动作的语义支持关系 |
| 模板审核后进入业务闭环 | 让人工判断发生在执行之前 | 审核负担及现场任务可用性 |

## 案例：资料不充分时怎样继续

**演示输入：** 制造业车间检查，部分设备与工艺信息尚未补全。选择库内法规，并填写已知作业条件。

**预期操作：** 检查生成的场景摘要与待补资料；逐条回查原文；将无法确认的内容保留为待核验；只把审核通过的条目进入现场任务；发现问题后记录整改与复查。

该案例是验收场景，不伪造已生成清单、真实企业身份或专业审查结论。

## 实现与规划

- **本地已实现：** Skill 读取、结构化生成、段落引用绑定与校验、一次纠正重试、模板/检查字段传递、JSON 持久化。
- **需要完善：** 组织身份与权限、审计、对象存储、法规版本治理与专家审核流程。
- **未提供证据：** 真实企业使用规模、审核时间节省、事故或违规率改善。

## 评估计划

由合适的领域审核者建立样本，覆盖信息充分、条件缺失、条文不适用、引用错误和模型服务失败等情况。

分别检查字段完整性、原文一致性、适用性、依据关系与现场可执行性；业务侧检查待核验是否被误计完成、整改记录是否保留上下文、复查能否追溯。指标应记录样本数、审核标准和失败实例，测量前不填入提升百分比。
